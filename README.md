# Projector USB

GUI-обёртка над ffmpeg/ffprobe на Rust + egui/eframe. Целевые ОС: Windows и macOS; Linux используется для проверки исходников.

## Сборка и запуск

Требуются актуальный Rust stable и ffmpeg/ffprobe, доступные в PATH процесса приложения.

```sh
cargo build --release --locked
cargo test --locked
cargo run --release --locked
```

Windows: результат `target/release/projector-usb.exe`. Для компиляции установите Visual Studio Build Tools с компонентом Desktop development with C++ и Rust через rustup. Добавьте папку `bin` установленного ffmpeg в пользовательский PATH, затем перезапустите терминал/сеанс.

macOS: установите Xcode Command Line Tools (`xcode-select --install`), Rust через rustup и ffmpeg, например `brew install ffmpeg`. Запускайте `target/release/projector-usb` из терминала с настроенным PATH. PATH приложений, запущенных из Finder, может отличаться от PATH терминала; это особенно важно для Homebrew в `/opt/homebrew/bin`.

Нативные сборки Windows и macOS Intel/Apple Silicon описаны в `.github/workflows/build.yml`. Готовые бинарные файлы под эти ОС в данный архив не включены. Workflow требуется запустить в собственном GitHub-репозитории.

Для macOS можно создать неподписанный `.app`:

```sh
mkdir -p 'Projector USB.app/Contents/MacOS'
cp target/release/projector-usb 'Projector USB.app/Contents/MacOS/'
cp packaging/Info.plist 'Projector USB.app/Contents/'
```

Подпись, notarization, инсталляторы и поставка ffmpeg не включены. Для запуска из Finder нужно обеспечить PATH процесса; приложение не ищет ffmpeg по жёстко заданным путям.

## Реализованные функции

- Два проводника: папки и только файлы с известными видео-расширениями, цветные рисованные значки, переходы Home/корень/наверх, редактирование пути, выбор диска, свободное место.
- Асинхронные снимки каталогов. При обновлении старый список остаётся доступным; снимок заменяется целиком, неизменённый снимок не присваивается заново. Выделение сохраняется до исчезновения элемента, идентификаторы фокуса привязаны к полному пути, состояние прокрутки — к папке.
- Индикаторы обновления и ошибок находятся вне списка в зарезервированных областях. Первоначальная загрузка может показывать спиннер вместо списка.
- Список подключённых дисков обновляется примерно раз в 2 секунды (зависит от длительности системных вызовов). На Windows используются Win32-функции, на macOS — getmntinfo. При исчезновении текущего тома проводник переходит в Home. Открытые дескрипторы каталогов в состоянии UI не хранятся.
- Сетевые диски: отображаются подключённые диски Windows и смонтированные тома macOS. Это не браузер сетевого окружения. UNC-путь можно ввести вручную в Windows. На macOS NAS следует сначала смонтировать средствами ОС.
- Поиск по маске `*`/`?` без учёта регистра; результаты приходят пакетами. Поиск отменяется при навигации или нажатии «Отменить». Символические ссылки рекурсивно не обходятся, чтобы избежать циклов.
- Удаление файла или папки в Destination с обязательным подтверждением. Папки удаляются рекурсивно, не в корзину. Объекты, используемые текущими задачами, защищены от удаления из UI.
- ffprobe: контейнер, длительность, дорожки с типом/кодеком/битрейтом. Отсутствующий в ffprobe битрейт показывается как «не указан», а не вычисляется приблизительно.
- Выбор первой или всех аудиодорожек; копирование аудио, AAC 256 kbit/s или MP3 256 kbit/s.
- Модальный диалог новой задачи: исходный путь, папка назначения, имя без расширения, начальный фокус и выделение текста, расширение отдельно, команда и копирование, Enter для запуска.
- Параллельные процессы ffmpeg, прогресс через `-progress pipe:1`, спиннер возле результата, счётчик задач и сумма оставшегося хронометража.
- Немодальное окно деталей с таблицей текущих задач, отменой, полными путями по наведению и логом последних 5 строк.
- Отмена принудительно завершает процесс; worker ожидает его завершения, затем удаляет незавершённый файл. При закрытии с активными задачами требуется подтверждение, приложение ждёт отмены и очистки.
- Папки и опции сохраняются в пользовательском профиле в `settings.json` через crate directories (Windows AppData, macOS Application Support).

## Принятые решения и ограничения

1. Начальный размер принят **1920 × 1024**, поскольку указанные 192 × 1024 противоречат минимальной ширине 1500. Минимум **1500 × 750**. Размеры задаются в логических единицах egui: физические пиксели зависят от DPI. Пропорции областей: 55% / 32% / остальное.
2. ffmpeg и ffprobe запускаются по имени из PATH через `Command::new`, без оболочечного интерпретатора и без фиксированного пути. Это сохраняет аргументы с пробелами/кириллицей и исключает shell injection. Алиасы и функции интерактивной оболочки не поддерживаются. Текст команды предназначен для POSIX shell на macOS и cmd.exe на Windows; PowerShell имеет иной синтаксис кавычек.
3. Видео не перекодируется (`-c:v copy`), все видеодорожки переносятся. Контейнер определяется по неизменённому расширению. Субтитры, вложения и data-дорожки не переносятся. Метаданные и главы копируются, если поддерживаются контейнером.
4. Контейнеры имеют собственные ограничения: не всякий контейнер допускает AAC или MP3. Для несовместимого сочетания задача завершается ошибкой ffmpeg, файл очищается; приложение не меняет контейнер скрытно. Например, WebM с AAC/MP3 обычно невозможен. Совместимость исходного видеокодека с проектором не гарантируется.
5. Перед процессом приложение резервирует результат через `create_new`; существующие файлы не перезаписываются. Затем ffmpeg получает `-y` для записи в собственный пустой резерв. Нельзя внешней программой подменять этот зарезервированный файл во время задачи. На USB FAT32 действует ограничение размера файла около 4 ГБ, независимо от приложения.
6. Длительность может отсутствовать. Тогда приложение явно показывает неизвестную длительность; суммарный остаток включает известную часть и счётчик неизвестных. Это остаток видеохронометража, не прогноз времени выполнения.
7. Список файлов не опрашивается периодически. Запуск задачи добавляет строку ожидаемого результата явно; прогресс меняет только её индикатор. Остальное обновляется вручную, при навигации, закрытии поиска или удалении.
8. На macOS локальные пользовательские тома `/Volumes/*` помечаются как USB/съёмные по расположению точки монтирования. Для строгого различения внешнего fixed-диска, USB и образа требуется расширение на DiskArbitration/IOKit.
9. Синхронный системный вызов чтения NAS внутри рабочего потока невозможно прервать обычным AtomicBool: UI остаётся отзывчивым, но worker может ждать ответа ОС; устаревшие результаты отбрасываются по generation. Дескрипторы закрываются после завершения чтения каталога. Поиск прекращается между такими операциями.
10. Сетевые ошибки и ошибки обновления не очищают последний успешный снимок. При первом открытии недоступной папки выполняется переход в Home. Ошибки процессов доступны в нижнем логе.

## Проверки

```sh
cargo fmt --check
cargo clippy -- -D warnings
cargo test --locked
# Нужны ffmpeg и ffprobe:
cargo test --locked -- --include-ignored
```

В текущей среде выполнены: Linux cargo check/build, clippy без предупреждений, 12 тестов (9 обычных + 3 интеграционных). Интеграционные тесты проверяют шесть сочетаний дорожек/кодеков на реальном ffmpeg, пути с пробелами/кириллицей, сохранение видеокодека, защиту существующего файла и удаление результата при отмене. GUI запускался под Xvfb без panic. Также выполнен cross-target `cargo check` для Windows x86_64 GNU и macOS Apple Silicon; это проверка типов, не нативная линковка и не запуск на целевых ОС.

Нативная приёмка Windows/macOS с физическим USB и NAS остаётся необходимой. Основные сценарии:

- Извлечь USB с открытой папкой в обоих проводниках без активной конвертации: устройство исчезает, оба проводника уходят в Home.
- Обновить большой каталог, сохранив выделение и скролл; проверить, что старый список доступен до применения снимка и нет пустого кадра.
- Начать поиск, затем сменить диск/Home: поздние результаты не должны попадать в новый список.
- Запустить несколько задач, отменить одну и закрыть приложение во время остальных: незавершённые файлы удалены.
- Проверить Finder PATH, UNC/NAS, read-only USB, недостаток места, несовместимый контейнер и файлы более 4 ГБ на FAT32.

## Структура

- `app.rs` — состояние приложения, события, компоновка, завершение.
- `explorer.rs` — проводник, атомарное применение снимка и поиск.
- `fs_worker.rs` — фоновые операции с каталогами, поиск, удаление.
- `drives.rs` — системное перечисление подключённых томов.
- `process.rs` — ffprobe, ffmpeg, чтение stdout/stderr, отмена/очистка.
- `dialogs.rs`, `icons.rs` — диалоги и рисованные пиктограммы.
- `model.rs`, `settings.rs` — модели, команда и настройки.
- `integration_tests.rs` — проверки на реальных процессах.
